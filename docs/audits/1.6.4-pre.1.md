# 1.6.4-pre.1 workspace audit

Scope: existing-session opening and composer models, responsive session status, scroll controls, request push actions, and connection-warning recovery.

## Findings and changes

- History opening waited on optional runtime inspection and transcript turn scanning. Display reads now use cached runtime status and keep unknown ownership locked. Mutating actions retain their fresh ownership checks, project checks, and archive guards.
- A newer session-status push could discard a late model catalog. Catalogs now apply independently of session revisions, retain request/system checks, and cannot be overwritten by an optional stale cache read. Existing conversations provide their saved model and reasoning preferences.
- Desktop conversation quota duplicated the sidebar. Only the inline mobile quota remains. The scroll control is centered above the composer and shows running dots, with reduced motion and mobile touch targets preserved.
- Question push notifications omitted question details and offered no direct choices. Short, non-secret single questions with at most two choices now carry exact answer mappings. Longer, duplicate-choice, private, and multi-part questions require session review. Authentication, owning-system routing, one-use notification actions, and unconfirmed-result reporting remain enforced.
- Old HTTP failures could override a recovered WebSocket. A healthy socket now retains live status. Passive presence failures do not generate repeated toasts. Connection banners wait three seconds, recovered offline notices disappear, and uncertain write failures remain visible.

## Failure paths reviewed

Reviewed missing/archived transcripts, unknown or stale ownership, optional status-storage failures, partial and stale session lists, host/system changes, cached composer settings, offline/reconnect and retry timing, duplicates and expired push actions, secret questions, truncated notification details, missing acknowledgements, and disconnected request owners. Existing queue capacity, storage recovery, startup recovery, action deadlines, and uncertain-write handling remain covered by the regression suite; this change adds no queue or persistent answer storage.

- Focused regression: 362 checks passed in 11 files; the final browser bridge check passed all 25 tests.
- Full regression: 2,742 tests passed in 218 files (713.23 seconds).
- Lint completed with zero errors and 3,665 style warnings. TypeScript caught a missing status annotation; that type-only correction passed both host and webview checks during final packaging.
- Production build, dashboard module checks, VSIX dependency/native-terminal checks, and packaging passed. Existing large-bundle warnings remain.
- Workspace browser checks passed at 1440x1000, 1024x768, 768x1024, 390x844, 320x667, and 844x390. These cover late model catalogs, composer controls, attachment removal, keyboard focus, centered running animation, reduced motion, the three-second warning grace period, and immediate recovery cleanup.
- Broader desktop and mobile dashboard checks passed, including inline mobile quota, account center, settings, history, workspace tools, and failed sends.
- The verified VSIX contains 191 matching manifest/runtime files. Installation matched all 190 runtime files, and the local host activated version `1.6.4-pre.1` after reload.
- Live desktop and mobile smoke checks passed against the installed host, including real existing histories and browser reconnects. One initial live opening exceeded the smoke check's 30-second wait; a diagnostic opening and the repeat smoke checks succeeded. Cold history reads remain variable: an idle-session read took about seven seconds, with eight model choices available. This does not establish that every history opens instantly.
