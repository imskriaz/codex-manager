# Manual action audit

Audited on 2026-10-14. Expected load: one user with multiple VS Code windows, browser clients and connected PCs, while quota polling, encrypted sync and session recovery run in the background.

"Instant" means the action starts immediately and its UI acknowledges pending work. Network requests, OAuth consent, model turns, ownership checks, durable storage, process termination and Git pushes still need their actual terminal result. A UI timeout does not cancel a mutation or prove that it failed; users must verify the state before retrying.

## Findings and changes

| Problem | Concrete effect | Change |
| --- | --- | --- |
| A browser snapshot could arrive before the UI subscribes | A healthy host remained on the Loading screen | Retain the latest page-local snapshot and replay it immediately when the dashboard becomes ready; refresh it normally afterward. Mutations are never replayed. |
| An open browser socket could stop acknowledging requests while HTTP remained available | Manual view refresh could not repair the dashboard | Send explicit read-only view refresh over HTTP with an 8 second deadline. Keep live updates on WebSocket and never resend mutations. |
| Every browser action awaited a complete dashboard snapshot | A completed switch, file save or cancellation appeared stuck while announcements, peers or storage loaded | Optional snapshots have a 250 ms budget; explicit refresh has a 5 second budget. Keep the action result and show a refresh warning. Rebuild current state after a late read. |
| Quota refresh awaited subscription enrichment even when its wait option was false | Subscription requests added up to two 15 second waits and competed with reset verification | Default enrichment runs separately, flushes its own writes and refreshes views. Explicit account-info refresh still awaits it and preserves rejection. |
| Import and OAuth follow-up work awaited profile, quota and sync network calls | An already-saved account remained pending offline | Optional profile, initial quota and follow-up sync waits are bounded to 500 ms, with visible partial-completion warnings. Shared JSON import uses the supplied identity and metadata without per-account profile requests. |
| Manual refresh awaited automatic selection and warning workflows | Session inspection or automatic reload delayed the refresh result | Evaluate automation separately after manual refresh. Background callers retain their automation workflow. |
| Single and batch refresh callers treated returned API errors as success | Offline provider responses inflated success counts and appeared as successful dashboard actions | Preserve errors in single results and batch failures; deduplicate requested batch IDs. Forced refresh bypasses the background maintenance cooldown. |
| Batch work slept before its first request | Every manual batch added an avoidable initial delay | Start the initial workers immediately; keep spacing for later requests. |
| UI globally blocked account controls during sync, OAuth, exports and refreshes | An unrelated action was unavailable for the whole network timeout | Retain global blocking for broad account mutations. Reads, exports and quota/sync work allow unrelated actions; backend ownership and operation locks still reject conflicts. |
| Batch client timeouts ignored account count | Longer batches timed out while still running | Scale batch deadlines by account count and retain explicit unknown-outcome retry guidance. |
| Manual switches used the automatic reload preparation budget | Optional recovery could add 5 seconds instead of the manual 500 ms budget | Mark reloads from manual switching as manual. Desktop restart preparation is also bounded; native optional restart prompts do not hold switch completion. |
| Completed chat turns and session mutations awaited unrelated discovery or history | Slow discovery hid completion, or failed reads incorrectly reported a completed mutation as failed | Sending no longer scans the full session list. Bound post-mutation discovery and transcript refresh to 500 ms; preserve history and show warnings. Apply known session changes locally if discovery is unavailable. |
| Successful Git commit/push awaited environment inspection | A successful mutation was reported as failed when later Git status failed | Bound follow-up inspection, retain the completed action and warn without advising another commit/push. Git status timeout is an error rather than a false non-Git result. |
| Dashboard notification suppression patched global functions per request | Concurrent requests restored wrappers out of order and could hide Command Palette errors | Share one temporary wrapper with a reference count and check the asynchronous request context before suppressing a notification. |
| Profile refresh held an old index across a network wait | A delayed result could overwrite a queued-account edit or another newly added account | Re-read current account/index and verify credentials after profile loading. Apply quota updates after optional profile work against the current index. |
| Explicit announcement refresh silently fell back and removed its cache first | An offline refresh reported success and discarded its usable cache | Preserve the cache and reject explicit fetch failures; passive reads retain their fallback. |
| Offline browser actions still attempted HTTP | A request that could not be sent could leave UI pending until a long timeout | Fail immediately with a request-scoped result. Never replay mutations on reconnect. |

## Failure audit and practical limits

- Switch/reload follow-up: dashboard actions return before scheduled restart; queued account changes survive cancelled reloads and permit already-active retries. Account selection is flushed before reload, and expired access tokens require successful refresh before auth changes.
- Dashboard recovery: persist the reopen marker before optional session discovery, cancel late disposal after a capture timeout, retain it through managed close, and clear it after user close or successful restoration. Failed/cancelled reloads invoke the same one-panel restoration path.
- Expired countdowns: process already-expired enabled/current account windows independently of periodic polling. Reuse a successful post-reset check, retry still-zero responses with exponential backoff, and recheck account existence, enablement and ownership under the refresh lease.
- Offline/stale/missing/partial: required ownership and credential checks fail visibly; stale selections are revalidated. Optional reads retain local/cached state and warn.
- Reconnect/retry/duplicates/queue-full: browser requests are not replayed; pending transport actions report unknown outcomes. Session request deduplication and the 128-request bound remain; batch IDs are deduplicated.
- Storage-full/reboot: required saves still flush before success. Atomic file saves preserve the original on failure. Reset-credit intent remains persisted across interrupted requests and requires reconciliation before retry.
- Timeout/failure: optional waits do not release a mutation's ownership lock or claim that it was cancelled. Required provider, Git, session RPC and process deadlines remain in their services. Errors remain available to the initiating dashboard or native notification.

No production account switching, token rotation, reset-credit consumption, file deletion, session deletion or external Git push was used for live smoke checks. Unit tests use disposable repositories and mocked provider failures. Required network/provider work can remain slow during outages or rate limiting; this audit does not promise instantaneous completion or fault-free operation on every external service.

The audit follows user action paths, not every background feature line by line. Live VS Code Command Palette interactions, cross-PC outages, real disk exhaustion and reboot recovery require a dedicated runtime environment; automated coverage verifies those failure paths where available. Packaging and regression outcomes are reported in the task response.
